### 2. Update Behavior

**Provider Update Logic:**

```go

            return fmt.Errorf("`encryption_at_host_enabled` cannot be set to `true` when `os_disk.0.security_encryption_type` is set to `DiskWithVMGuestState`")
        }
    }
```

**Key Observation:** The field is updateable (no ForceNew: true), but the Azure API requires the VM to be deallocated before updating this field. The provider handles this by setting `shouldDeallocate = true`, which triggers VM deallocation before the update.

**AzAPI Behavior:** When using `azapi_resource`, the AzAPI provider will send the update request to Azure. If Azure requires deallocation, the API will return an error. This is consistent with Azure API behavior and matches the experience users would have with the AzureRM provider when the API fails.

**No ForceNew Needed:** Since the provider schema does not have `ForceNew: true`, we should NOT add this field to `replace_triggers_external_values`. The field is meant to be updateable, and Azure's requirement for deallocation is an operational constraint, not a Terraform state management concern.
