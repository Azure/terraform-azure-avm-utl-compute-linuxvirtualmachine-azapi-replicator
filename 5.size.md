### ForceNew Behavior
The `size` field does **NOT** have `ForceNew: true` in the schema. However, the Update method shows special behavior:

**Evidence from Update method**:
```go
if d.HasChange("size") {
	shouldUpdate = true
	shouldShutDown = true
	vmSize := d.Get("size").(string)

	// Azure will auto-reboot this for us, providing this machine will fit on this host
	// otherwise we need to shut down the VM to move it to another host to be able to use this size
	availableOnThisHost := false
	sizes, err := client.ListAvailableSizes(ctx, *id)
	if err != nil {
		return fmt.Errorf("retrieving available sizes for Linux %s: %+v", id, err)
	}

	if sizes.Model != nil && sizes.Model.Value != nil {
		for _, size := range *sizes.Model.Value {
			if size.Name == nil {
				continue
			}

			if strings.EqualFold(*size.Name, vmSize) {
				availableOnThisHost = true
				break
			}
		}
	}

	if !availableOnThisHost {
		log.Printf("[DEBUG] Requested VM Size isn't available on the Host - must switch host to resize..")
		shouldDeallocate = true
	}

	update.Properties.HardwareProfile = &virtualmachines.HardwareProfile{
		VMSize: pointer.To(virtualmachines.VirtualMachineSizeTypes(vmSize)),
	}
}
```

**Update Behavior**:
1. **Always requires shutdown**: `shouldShutDown = true`
2. **Conditionally requires deallocation**: If the new size is not available on the current host, the VM must be deallocated to move to a different host
3. **Azure handles the logic**: The provider calls `ListAvailableSizes` to check if the size is available on the current host
4. **No ForceNew**: The field is updateable via the Update method

**Decision**: Since the field is updateable (not ForceNew), we do NOT add it to `replace_triggers_external_values`. The Update method in the provider handles size changes without forcing resource recreation. Azure may automatically reboot the VM or require deallocation depending on host availability, but this is handled by the Azure API, not by Terraform's ForceNew mechanism.

### Update Phase Handling
The `size` field can be updated in-place (with shutdown/deallocation as needed). Since it's updateable and not ForceNew, no special handling in `replace_triggers_external_values` is required.

### Edge Case Analysis
1. **Update to unavailable size on current host**: Azure provider handles this by checking `ListAvailableSizes` and conditionally deallocating if needed. With AzAPI, the Azure API will handle this automatically - if the size requires host change, the API will fail with an appropriate error message, or the user can manually deallocate before updating.

2. **Empty string**: Validation block prevents empty strings at plan time.

3. **Case sensitivity**: The provider uses `strings.EqualFold` for size comparison in Update, suggesting case-insensitive matching. However, Azure VM sizes are typically provided in a specific case format (e.g., `Standard_F2`). The validation only checks for non-empty, relying on Azure API for format validation.
