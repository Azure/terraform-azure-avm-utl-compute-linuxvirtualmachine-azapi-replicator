```hcl

```

If the user provides a value, it overrides the default 45-minute timeout. If not provided (null), the Terraform SDK uses the default timeout defined in the provider.

### No Validation Required

### No ForceNew Logic

## Critical Review & Edge Cases

### Null Semantics
- **`var.timeouts = null`**: Entire timeouts block is null → Uses provider default (45m for create)
- **`var.timeouts.create = null`**: Specific timeout field is null → Uses provider default (45m)
- **`var.timeouts.create = "1h"`**: Uses 1 hour timeout instead of default

### Boundary Conditions
- **Very short durations** (e.g., "1s"): Valid but may cause premature timeout for VM creation
- **Very long durations** (e.g., "24h"): Valid and may be needed for complex deployments
- **Zero duration**: Not typically valid for timeouts
- **Invalid format** (e.g., "45 minutes"): Rejected by Terraform core validation

### Idempotency
Timeout configuration is idempotent. The same timeout value always produces the same waiting behavior. Changing timeout values does not affect the resource state, only how long Terraform waits for operations.

### Safe References
The reference `var.timeouts.create` is safe because:
1. It's accessed within a conditional block: `var.timeouts != null ? {...} : null`
2. When `var.timeouts` is null, the entire expression evaluates to null
3. When `var.timeouts` is non-null, accessing `.create` is safe (may return null, which is valid)

### Edge Case Analysis

#### Case 1: Partial Timeout Configuration
User sets only `create` timeout, others remain default:
```hcl
timeouts = {
  create = "2h"
}
```
Result: Create uses 2 hours, read/update/delete use provider defaults. ✅ VALID

#### Case 2: All Timeouts Null
```hcl
timeouts = {
  create = null
  delete = null
  read   = null
  update = null
}
```
Result: All operations use provider defaults. ✅ VALID

#### Case 3: Empty Object vs Null
```hcl
# Case A: timeouts = null
# Case B: timeouts = {}
```
Both cases result in `local.timeouts = null` in Case A, or `local.timeouts = { create = null, ... }` in Case B. Both are valid and use provider defaults. ✅ VALID

#### Case 4: Duration Format Variations
ISO 8601 allows multiple formats:
- `"45m"` - Simple duration (45 minutes)
- `"PT45M"` - ISO 8601 period (45 minutes)
- `"1h30m"` - Compound duration (1 hour 30 minutes)

All are valid and handled by Terraform core. ✅ VALID
