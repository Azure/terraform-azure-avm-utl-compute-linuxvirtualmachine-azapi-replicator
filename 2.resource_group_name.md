# Task #2: resource_group_name - Proof Document

## Summary

Implemented the `resource_group_name` field for `azurerm_linux_virtual_machine` to `azapi_resource` migration. This field is a Required, ForceNew argument that specifies the Resource Group where the VM should be created. Since azapi_resource uses `parent_id` instead of resource_group_name, the field is converted to a Resource Group ID and used in `azapi_header.parent_id`. The `resource_group_id` variable was already created by Task #1 as per executor.md instructions.

## Shadow Implementation

### migrate_variables.tf
```hcl
variable "resource_group_id" {  # <-
  type        = string  # <-
  description = "(Required) The ID of the Resource Group in which the Linux Virtual Machine should exist. Changing this forces a new resource to be created."  # <-
  nullable    = false  # <-

  validation {  # <-
    condition     = can(regex("^/subscriptions/[a-fA-F0-9-]+/resourceGroups/[^/]+$", var.resource_group_id))  # <-
    error_message = "resource_group_id must be a valid Azure Resource Group ID in the format: /subscriptions/{subscriptionId}/resourceGroups/{resourceGroupName}"  # <-
  }  # <-
}  # <-

locals {  # <-
  resource_group_id = var.resource_group_id  # <-
}  # <-
```

## Special Handling

### ForceNew Behavior

The `resource_group_name` field has `ForceNew: true` in the provider schema (via commonschema.ResourceGroupName()). This means any change to the resource group requires resource replacement.

**Implementation:**
```hcl
replace_triggers_external_values = {
  resource_group_id = { value = var.resource_group_id }
}
```

The value is wrapped in an object to ensure the key remains stable. The full value is tracked to detect any changes.

### Validation

The provider uses standard Azure Resource Group name validation. In our implementation, we validate the full Resource Group ID format to ensure it's a valid Azure Resource Group ID.

**Validation in migrate_variables.tf:**
```hcl
validation {
  condition     = can(regex("^/subscriptions/[a-fA-F0-9-]+/resourceGroups/[^/]+$", var.resource_group_id))
  error_message = "resource_group_id must be a valid Azure Resource Group ID in the format: /subscriptions/{subscriptionId}/resourceGroups/{resourceGroupName}"
}
```

This ensures:
1. The ID follows the correct format: `/subscriptions/{subscriptionId}/resourceGroups/{resourceGroupName}`
2. The subscription ID is a valid GUID
3. The resource group name is not empty

## Critical Review & Edge Case Analysis

### Null Semantics
- **Variable:** `nullable = false` - the resource_group_id must always be provided
- **Required:** Yes, this is a required argument
- **Meaning:** Resource Group ID cannot be null; it must be a valid Resource Group ID string

### Boundary Conditions
- **Empty string:** Rejected by validation (regex requires non-empty resourceGroupName)
- **Invalid format:** Rejected by validation (must match Azure Resource Group ID format)
- **Invalid subscription GUID:** Rejected by validation (must be valid GUID format)
- **Missing segments:** Rejected by validation (must have both subscriptions and resourceGroups segments)

### Idempotency
- The resource_group_id is a simple string value with no order-dependent behavior
- ForceNew ensures that any change to the Resource Group creates a new VM (idempotent)
- No array operations or merge logic involved

### Safe References
- Direct reference to `var.resource_group_id` is safe as it's a required, non-nullable field
- Reference to `local.resource_group_id` is safe as it's directly assigned from the variable
- No nested property access required
- No risk of null pointer exceptions

### Edge Cases
1. **Case sensitivity:** Azure Resource IDs are case-insensitive, but the validation preserves the case provided by the user
2. **Resource Group must exist:** Azure API will validate that the Resource Group exists when creating the VM
3. **Subscription access:** User must have access to the subscription specified in the Resource Group ID
4. **Cross-subscription scenarios:** The subscription in the Resource Group ID should match the provider's subscription context
