```go
func ExpandSystemAndUserAssignedMap(input []interface{}) (*SystemAndUserAssignedMap, error) {
    identityType := TypeNone
    identityIds := make(map[string]UserAssignedIdentityDetails, 0)

    if len(input) > 0 {
        raw := input[0].(map[string]interface{})
        typeRaw := raw["type"].(string)
        if typeRaw == string(TypeSystemAssigned) {
            identityType = TypeSystemAssigned
        }
        if typeRaw == string(TypeSystemAssignedUserAssigned) {
            identityType = TypeSystemAssignedUserAssigned
        }
        if typeRaw == string(TypeUserAssigned) {
            identityType = TypeUserAssigned
        }

        identityIdsRaw := raw["identity_ids"].(*schema.Set).List()
        for _, v := range identityIdsRaw {
            identityIds[v.(string)] = UserAssignedIdentityDetails{
                // intentionally empty since the expand shouldn't send these values
            }
        }
    }

    if len(identityIds) > 0 && (identityType != TypeSystemAssignedUserAssigned && identityType != TypeUserAssigned) {
        return nil, fmt.Errorf("`identity_ids` can only be specified when `type` is set to %q or %q", string(TypeSystemAssignedUserAssigned), string(TypeUserAssigned))
    }

    return &SystemAndUserAssignedMap{
        Type:        identityType,
        IdentityIds: identityIds,
    }, nil
}
```

```go
if d.HasChange("identity") {
```

## Critical Review & Edge Case Analysis

### Null Semantics

- `var.identity == null` → `identity` field is omitted from `azapi_header` (no managed identity configured)
- `var.identity != null && var.identity.identity_ids == null` → `userAssignedIdentities` is `null` in the Azure API (only system-assigned identity, or type is SystemAssigned)
- `var.identity != null && var.identity.identity_ids != null` → `userAssignedIdentities` is a map with identity IDs as keys

**Important:** The Azure API treats `null` differently from empty map `{}`:
- `null`: No user-assigned identities (appropriate when `type` is `SystemAssigned`)
- `{}`: Empty list of user-assigned identities (would be invalid - validation prevents this scenario)

Our implementation correctly uses `null` when `identity_ids` is null.

### Boundary Conditions

**Empty Set:**
- If `var.identity.identity_ids` is an empty set `[]`, the for expression creates an empty map `{}`
- The cross-field validation (Task #69) allows empty `identity_ids` even when `type` requires them - this matches provider behavior
- An empty map means "no user-assigned identities"

**Set Ordering:**
- Terraform sets are unordered, but the map keys in the API payload may have ordering
- This is not a concern for idempotency - Azure API treats the map as unordered
- The for expression creates a deterministic map based on the set contents

**Duplicate Prevention:**
- Terraform sets automatically prevent duplicates
- No additional deduplication logic needed

### Idempotency

The implementation is idempotent:
- The same set of identity IDs will always produce the same map structure
- The for expression creates a stable map where each ID maps to an empty object
- No order-dependent operations
- Applying the same configuration multiple times produces identical results

### Safe References

- The reference `var.identity.identity_ids` is protected by the parent null check `var.identity != null ? {...} : null`
- Additional null check `var.identity.identity_ids != null ? {...} : null` ensures safe handling when identities are not specified
- No nested access issues

### Edge Case: Type Transitions

**Scenario 1: Adding User-Assigned Identity**
- Before: `type = "SystemAssigned"`, `identity_ids = null`
- After: `type = "SystemAssigned, UserAssigned"`, `identity_ids = ["id1"]`
- Result: Update succeeds, map created with one entry

**Scenario 2: Removing User-Assigned Identity**
- Before: `type = "SystemAssigned, UserAssigned"`, `identity_ids = ["id1", "id2"]`
- After: `type = "SystemAssigned, UserAssigned"`, `identity_ids = ["id1"]`
- Result: Update succeeds, map updated to contain only one entry
- Note: Provider uses PUT (not PATCH) to properly remove identities

**Scenario 3: Changing Identity Type**
- Before: `type = "UserAssigned"`, `identity_ids = ["id1"]`
- After: `type = "SystemAssigned"`, `identity_ids = null`
- Result: Update succeeds, identity type changed, user-assigned identities removed

All transitions are handled correctly by the Azure API through the update operation. The provider's use of PUT (CreateOrUpdate) instead of PATCH ensures proper removal of user-assigned identities.
