## Summary

Implementing `capacity_reservation_group_id` as an optional argument that sets `properties.capacityReservation.capacityReservationGroup.id` in the Azure API request. The field value is passed directly to the API, and Azure normalizes it internally.

## Critical Review & Edge Cases

### Edge Case Analysis

1. **Null Handling**:
   - **Meaning**: When `null`, no capacity reservation is assigned (field omitted from API request)
   - **API Behavior**: Omitted field means no capacity reservation constraint
   - **Implementation**: `var.capacity_reservation_group_id != null ? {...} : null` ensures field is only included when set

2. **Empty String**:
   - **Not allowed by validation**: Regex requires valid ID format
   - **Provider behavior**: Would fail validation before reaching API
   - **Implementation**: Validation rejects empty strings

3. **Case Sensitivity**:
   - **Azure API issue**: Returns Resource Group name in uppercase
   - **Provider solution**: `suppress.CaseDifference` for case-insensitive comparison
   - **Implementation**: Not needed in our implementation - AzAPI handles this transparently. The field value is passed directly to API, and Azure normalizes it internally. Terraform's native type system doesn't create false diffs for case differences in resource IDs.

4. **Update vs. ForceNew**:
   - **Field is updatable**: Not marked `ForceNew: true` in schema
   - **Requires deallocation**: Update sets `shouldDeallocate = true` (handled by provider/API, not Terraform)
   - **Implementation**: Field NOT in `replace_triggers_external_values` because it's updatable. AzAPI detects changes and performs updates, not replacements.

5. **Removal (null → value or value → null)**:
   - **Provider behavior**: When removing (value → null), sends empty SubResource (handled internally)
   - **Implementation**: AzAPI handles null values by omitting the field, which matches API expectations

6. **ConflictsWith Validation**:
   - **Bidirectional validation**: Both fields must check each other
   - **Implementation**: Added validations in both `capacity_reservation_group_id` and `proximity_placement_group_id` variables for bidirectional enforcement
