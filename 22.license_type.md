### Update Behavior

**Evidence from Update method:**
```go
if d.HasChange("license_type") {
    shouldUpdate = true

    licenseType := "None"
    if v, ok := d.GetOk("license_type"); ok {
        licenseType = v.(string)
    }
    update.Properties.LicenseType = pointer.To(licenseType)
}
```

**Key Observation:** When `license_type` is removed (set to null), the provider sends "None" to the API during update. However, during create, if not provided, it's simply omitted (not sent).

**Analysis:** This is a quirk of the Update API - it requires explicit "None" to clear the license type. However, in our AzAPI implementation:
- When `var.license_type = null`, the field will be `null` in the body
- AzAPI's `ignore_null_property = true` will omit null properties from the request
- For updates where we want to clear the license_type, users would need to explicitly set it to an empty string or similar, but since the validation doesn't allow empty strings, **users cannot clear a license_type once set**

**Decision:** This matches the provider behavior where once a license_type is set, it can only be changed to another valid value, not removed. The implementation is correct as-is.

## Critical Review & Edge Cases

### Null Semantics

**When null:**
- During Create: Field is omitted from API request (null in body, ignored by `ignore_null_property = true`)
- During Update: With our implementation, field is omitted, which means no change to existing value
- Provider behavior: On create, omits field. On update, sends "None" to clear it.

**Difference:** Our implementation cannot explicitly clear a license_type once set (would require sending "None" which isn't a valid validation value). This is acceptable because:
1. The provider's validation doesn't allow "None" as a user input
2. Users can change between valid license types but cannot remove licensing once applied
3. This matches Azure's licensing model where once a license is applied, it should be changed rather than removed
