## Critical Review & Edge Case Analysis

### Edge Case 1: Null vs Empty Map
- **Null (`var.tags = null`):** Passed as-is to `azapi_header.tags`, resulting in no tags on the resource
- **Empty Map (`var.tags = {}`):** Passed as empty map, also resulting in no tags
- **Behavior:** Both are semantically equivalent in Azure - resource has no tags

### Edge Case 2: Tag Updates
- **Scenario:** User changes `tags` from `{env = "dev"}` to `{env = "prod"}`
- **Expected Behavior:** In-place update (no replacement)
- **Implementation:** Correct - `tags` is not in `replace_triggers_external_values`, so changes trigger updates only

### Edge Case 3: Tag Removal
- **Scenario:** User changes `tags` from `{env = "dev"}` to `null` or `{}`
- **Expected Behavior:** All tags removed from resource
- **Implementation:** Correct - AzAPI will send empty/null tags, removing all tags

### Edge Case 4: Case Sensitivity
- **Azure Behavior:** Tag keys are case-insensitive in Azure (e.g., `Env` and `env` are treated as the same key)
- **Provider Behavior:** The provider does not normalize tag key casing; it passes keys as-is to Azure
- **Implementation:** Correct - We pass `var.tags` directly without normalization, matching provider behavior

### Edge Case 5: Special Characters in Values
- **Scenario:** Tag values with special characters, unicode, spaces
- **Azure Behavior:** Azure allows most characters in tag values (with length limits)
- **Implementation:** Correct - No sanitization or validation, values passed as-is (matches provider)
