## Create Phase Verification
The `timeouts` block is a Terraform meta-argument, not an Azure API field. It does not appear in any Create/Update/Delete operations in the provider source code. Timeouts are handled by the Terraform SDK framework itself and configure how long operations should wait before timing out.

From the resource function:

**Decision:** This is NOT part of the Azure API request body. It's a Terraform SDK meta-argument that controls operation timeouts. In the AzAPI provider, timeouts are specified directly on the resource block.

## Special Handling

### Timeouts Meta-Argument
The `timeouts` block is unique because:
1. **Not API Data**: Unlike other blocks, this doesn't map to Azure API fields
2. **Framework-Level**: Handled by Terraform SDK framework, not provider code
3. **No Expansion**: There's no `expand` function for timeouts in the provider
4. **SDK Defaults**: The Terraform SDK provides default timeout values if not specified

### Implementation Pattern

When `var.timeouts` is `null`, the entire timeouts block is not set, allowing the AzAPI provider to use its own defaults.

## Critical Review & Edge Cases

### Null Semantics
- **`var.timeouts = null`**: No timeouts configuration → `local.timeouts = null` → AzAPI provider uses its defaults
- **Individual timeout `null`**: When `var.timeouts` is set but a specific timeout (e.g., `create`) is `null` → That specific timeout uses AzAPI provider default
- **Empty string `""`**: Invalid for timeout values (must be valid ISO 8601 duration)

### Boundary Conditions
- **Zero duration**: Not typically valid for timeouts
- **Very large durations**: Limited by Terraform's maximum timeout values
- **Invalid format**: Must be ISO 8601 duration format (e.g., "45m", "PT45M")

### Idempotency
- Timeouts configuration is idempotent - same values always produce same waiting behavior
- Changing timeout values doesn't affect resource state, only operation behavior

### Safe References
- The conditional `var.timeouts != null ? {...} : null` ensures we only create the timeouts object when explicitly configured
- Each child field reference `var.timeouts.create`, `var.timeouts.delete`, etc. is safe because we've already verified `var.timeouts != null`

### Edge Case Analysis
1. **Partial Configuration**: User can set only some timeouts (e.g., only `create`), others default
2. **Format Validation**: Terraform validates ISO 8601 duration format automatically
3. **Backwards Compatibility**: Null timeouts block maintains backward compatibility with modules that don't specify timeouts
4. **Operation Specificity**: Each operation (create/read/update/delete) can have different timeout values
