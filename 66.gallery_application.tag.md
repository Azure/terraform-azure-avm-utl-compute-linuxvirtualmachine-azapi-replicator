## Critical Review & Edge Case Analysis

### Null Semantics

**Question:** What does null mean for this field?

**Provider Behavior:**
```go
Tags: pointer.To(config["tag"].(string)),
```

**Analysis:**
- When `app.tag == null` in Terraform, `config["tag"]` returns empty string `""` (Go zero value for string)
- Provider wraps this: `pointer.To("")` → pointer to empty string
- This sends `"tags": ""` to API

**Our Implementation:**
```hcl
tags = app.tag
```

**With AzAPI provider:**
- When `app.tag == null`, our implementation sends `tags = null`
- With `ignore_null_property = true`, null fields are omitted from JSON
- This creates a difference: provider sends `"tags": ""`, we omit the field

**Resolution:**
- Azure API schema shows `tags` is optional
- The provider comment states: "this is a pass through value that we just add to the model but don't depend on"
- Empty string vs omitted field should have no functional difference for a passthrough value
- Our implementation is acceptable and cleaner (omit unnecessary empty fields)

### Whitespace Handling

**Validation Check:** `length(trimspace(app.tag)) > 0`

**Cases:**
- `null` → ✅ Allowed (bypasses validation via null check)
- `""` → ❌ Rejected (trimspace("") has length 0)
- `"   "` → ❌ Rejected (trimspace("   ") has length 0)
- `"value"` → ✅ Allowed
- `" value "` → ✅ Allowed (trimspace(" value ") = "value", length > 0)

**Edge Case:** What if user provides `" value "` with leading/trailing spaces?

**Our behavior:** Validation passes, value sent as-is: `tags = " value "`

**Provider behavior:** Validation passes, value sent as-is: `Tags: pointer.To(" value ")`

**Result:** ✅ Identical behavior - both preserve whitespace in the value.
