## Edge Case Analysis

### Null Semantics
- **null value:** Azure auto-generates the OS disk name. This is the Computed behavior.
- **empty string (""):** Treated as null (no value sent to API), allowing Azure to auto-generate.
- **non-empty string:** Explicitly set as the OS disk name.

### Boundary Conditions
- **Empty string:** Converted to null to match provider behavior (empty check in expand function).
- **Whitespace-only strings:** Terraform will pass through as-is, but Azure API will validate.
- **Length/format restrictions:** Azure API enforces disk naming rules, no pre-validation needed as this would duplicate API logic.

### Idempotency
- **First apply with null:** Azure generates name, stored in state.
- **Subsequent applies:** If null continues to be null, no change. If changed to non-null, triggers replacement.
- **Value change:** Any change to non-null value triggers replacement (ForceNew).

### Safe References
- **Conditional access:** `var.os_disk != null ? var.os_disk.name : null` safely checks parent block existence before accessing field.
- **Empty string check:** `var.os_disk.name != null && var.os_disk.name != ""` prevents sending empty strings to API.

### Special Considerations
- **Auto-generated names:** When null, Azure generates names following pattern similar to `{vm-name}_OsDisk_{timestamp}`.
- **Replacement behavior:** Any change to the name (including null → value or value → null) will trigger VM replacement due to ForceNew.
