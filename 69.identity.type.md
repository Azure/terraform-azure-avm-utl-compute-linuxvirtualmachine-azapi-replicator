```go
func ExpandSystemAndUserAssignedMap(input []interface{}) (*SystemAndUserAssignedMap, error) {
    identityType := TypeNone
    identityIds := make(map[string]UserAssignedIdentityDetails, 0)

    if len(input) > 0 {
        raw := input[0].(map[string]interface{})
        typeRaw := raw["type"].(string)
        if typeRaw == string(TypeSystemAssigned) {
            identityType = TypeSystemAssigned
        }
        if typeRaw == string(TypeSystemAssignedUserAssigned) {
            identityType = TypeSystemAssignedUserAssigned
        }
        if typeRaw == string(TypeUserAssigned) {
            identityType = TypeUserAssigned
        }

        identityIdsRaw := raw["identity_ids"].(*schema.Set).List()
        for _, v := range identityIdsRaw {
            identityIds[v.(string)] = UserAssignedIdentityDetails{
                // intentionally empty since the expand shouldn't send these values
            }
        }
    }

    if len(identityIds) > 0 && (identityType != TypeSystemAssignedUserAssigned && identityType != TypeUserAssigned) {
        return nil, fmt.Errorf("`identity_ids` can only be specified when `type` is set to %q or %q", string(TypeSystemAssignedUserAssigned), string(TypeUserAssigned))
    }

    return &SystemAndUserAssignedMap{
        Type:        identityType,
        IdentityIds: identityIds,
    }, nil
}
```

The `Identity` field is assigned directly to the `VirtualMachine` struct at the root level, not nested under `Properties`. The expand function processes the `type` field and assigns it to the `Type` field of the `SystemAndUserAssignedMap` struct.

**Update Method Evidence:**

```go
if d.HasChange("identity") {
```

### Issues Identified

#### Issue 1: Incorrect Cross-Field Validation Logic

**Problem:**
The cross-field validation at lines 583-589 in variables.tf had inverted logic that didn't match the provider's expand function behavior.

**Executor's Implementation:**
```hcl
validation {
  condition = (
    var.identity == null ||
    (var.identity.type != "UserAssigned" && var.identity.type != "SystemAssigned, UserAssigned") ||
    (var.identity.identity_ids != null && length(var.identity.identity_ids) > 0)
  )
  error_message = "identity_ids can only be specified when type is set to \"UserAssigned\" or \"SystemAssigned, UserAssigned\"."
}
```

**Why This Violates executor.md:**
The logic doesn't match the provider's expand function. From the provider source (lines 102-104):

```go
if len(identityIds) > 0 && (identityType != TypeSystemAssignedUserAssigned && identityType != TypeUserAssigned) {
    return nil, fmt.Errorf("`identity_ids` can only be specified when `type` is set to %q or %q", string(TypeSystemAssignedUserAssigned), string(TypeUserAssigned))
}
```

The provider checks: "Error if identity_ids has items AND type is NOT one of the allowed values"

**Provider's Actual Behavior:**
- If `identity_ids` is set with items AND `type` is `"SystemAssigned"` → **ERROR**
- If `identity_ids` is set with items AND `type` is `"UserAssigned"` → **ALLOWED**
- If `identity_ids` is set with items AND `type` is `"SystemAssigned, UserAssigned"` → **ALLOWED**
- If `identity_ids` is null/empty → **ALLOWED** (regardless of type)

**Expected Behavior:**
The validation should allow the case when:
1. identity is null, OR
2. identity_ids is null, OR
3. identity_ids is empty, OR
4. type is one of the allowed values ("UserAssigned" or "SystemAssigned, UserAssigned")

**Root Cause:**
Executor incorrectly applied De Morgan's law or misunderstood the provider's validation intent. The original logic checked if identity_ids IS present when type requires it, but should check if identity_ids is NOT present when type forbids it.

### Corrections Made

#### Fix 1: Corrected Cross-Field Validation Logic

**Changed Files:**
- `variables.tf`: Lines 582-590

**New Implementation:**
```hcl
validation {
  condition = (
    var.identity == null ||
    var.identity.identity_ids == null ||
    length(var.identity.identity_ids) == 0 ||
    var.identity.type == "UserAssigned" ||
    var.identity.type == "SystemAssigned, UserAssigned"
  )
  error_message = "identity_ids can only be specified when type is set to \"UserAssigned\" or \"SystemAssigned, UserAssigned\"."
}
```

**Why This is EXACT:**
This directly translates the provider's validation logic:
- Provider error condition: `len(identityIds) > 0 && (type != allowed1 && type != allowed2)`
- Validation passes when error condition is FALSE
- Using De Morgan's law correctly: `!(A && B)` = `!A || !B`
- `!(len > 0 && (type != a && type != b))` = `len == 0 || type == a || type == b`
- Adding null safety: `identity == null || identity_ids == null || ...`

**Verification:**
- Scenario 1: `type = "SystemAssigned"`, `identity_ids = ["id1"]` → condition = `false || false || false || false || false` = **FALSE** → ERROR ✅
- Scenario 2: `type = "UserAssigned"`, `identity_ids = ["id1"]` → condition = `false || false || false || true || false` = **TRUE** → PASS ✅
- Scenario 3: `type = "SystemAssigned, UserAssigned"`, `identity_ids = ["id1"]` → condition = `false || false || false || false || true` = **TRUE** → PASS ✅
- Scenario 4: `type = "SystemAssigned"`, `identity_ids = null` → condition = `false || true || ... ` = **TRUE** → PASS ✅
- Scenario 5: `type = "UserAssigned"`, `identity_ids = []` → condition = `false || false || true || ...` = **TRUE** → PASS ✅
