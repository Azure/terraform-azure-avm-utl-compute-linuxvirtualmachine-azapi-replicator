## Special Handling

### Default Value Logic

**Provider Behavior:**
The provider schema has `Default: string(virtualmachines.DiffDiskPlacementCacheDisk)` which is `"CacheDisk"`.

**Go Type Assertion:**
```go
Placement: pointer.To(virtualmachines.DiffDiskPlacement(diffDiskRaw["placement"].(string)))
```

When the user doesn't specify the `placement` field, the provider schema's default value (`"CacheDisk"`) is used. The expand function retrieves this value (either user-specified or default) and assigns it to the API struct.

**Implementation:**
We need to replicate this default behavior in our implementation. Since the variable is defined as `optional(string)` without an inline default in the type definition, when the user doesn't specify the field, it will be `null`. We must apply the default value `"CacheDisk"` in the locals:

```hcl
placement = var.os_disk.diff_disk_settings.placement != null ? var.os_disk.diff_disk_settings.placement : "CacheDisk"
```

**Rationale:** This matches the provider's behavior where the schema default is always applied. The expand function always sends a value to the API (never null for this field when diff_disk_settings is set).

### ForceNew Logic

The provider schema marks this field as `ForceNew: true`, meaning any change to this field triggers resource replacement.

**Implementation:** Added to `replace_triggers_external_values` with wrapped value, including the default value application:

```hcl
os_disk_diff_disk_settings_placement = { value = var.os_disk != null && var.os_disk.diff_disk_settings != null ? (var.os_disk.diff_disk_settings.placement != null ? var.os_disk.diff_disk_settings.placement : "CacheDisk") : null }
```

**Critical:** The ForceNew tracking MUST include the default value logic. When the user doesn't specify placement:
- First apply: `null` → default applied → `"CacheDisk"` sent to API
- Subsequent applies: If still null, default applied → `"CacheDisk"` (no change, stable)
- If user changes to explicit value or changes existing value → triggers replacement

**Rationale:** The field is `ForceNew: true` in the provider schema, and there's no CustomizeDiff logic that would conditionally apply ForceNew. We use Mode 1 (Direct Value Tracking) from executor.md. The default value must be applied in the ForceNew tracking to ensure consistent behavior.
