# Task #60 - boot_diagnostics.storage_account_uri - Block Argument

## Summary
Implemented the `storage_account_uri` argument within the `boot_diagnostics` block, which maps to `properties.diagnosticsProfile.bootDiagnostics.storageUri` in the Azure API. The implementation handles three states exactly as the provider does: (1) when boot_diagnostics is null → disabled with `enabled=false` and empty storageUri (handled by skeleton), (2) when boot_diagnostics is set but storage_account_uri is null → managed boot diagnostics with `enabled=true` and empty storageUri, (3) when storage_account_uri has a value → custom storage boot diagnostics with `enabled=true` and storageUri set to the provided value. The hidden field `enabled` is always set based on whether boot_diagnostics block exists.

## Edge Case Analysis

1. **Null vs Empty String for storage_account_uri:**
   - `storage_account_uri = null` → Empty storageUri `""` (managed boot diagnostics)
   - `storage_account_uri = ""` → Empty storageUri `""` (same as null, managed boot diagnostics)
   - The ternary operator correctly handles both cases, evaluating `null` to use the default empty string

2. **Block State Transitions:**
   - Null → Empty block: Enabled managed boot diagnostics (updateable)
   - Null → Block with URI: Enable custom storage boot diagnostics (updateable)
   - Empty block → Block with URI: Switch from managed to custom storage (updateable)
   - Block with URI → Empty block: Switch from custom to managed storage (updateable)
   - Any → Null: Disable boot diagnostics (updateable)
   - No ForceNew, all transitions are updates

3. **Empty String in API:**
   - Provider always sends `storageUri` field, even when empty
   - Empty string is semantically meaningful: it indicates managed boot diagnostics (when `enabled = true`)
   - When disabled (`enabled = false`), empty `storageUri` is also always sent

4. **Idempotency:**
   - When boot_diagnostics is null: Always outputs same disabled state
   - When boot_diagnostics is set: Always outputs `enabled = true`
   - When storage_account_uri is null: Always outputs empty string for storageUri
   - When storage_account_uri has value: Always outputs that exact value
   - No order-dependent logic, fully idempotent

5. **Safe References:**
   - `var.boot_diagnostics != null` check before accessing nested field
   - `var.boot_diagnostics.storage_account_uri != null` check with proper fallback to empty string
   - All nested field accesses are safe
